### 项目名称
Dice Slapper — 骰子拍桌放置/点击增量游戏

### 目标（Phase 1）
- 实现可信的实体骰子物理与外观（3D 渲染 + 碰撞 + 滚动 + 停止判定）。
- 提供最小可玩的交互：玩家在桌面上“拍击”造成骰子弹跳，产生随机但可控的结果。
- 桌面区域记分：根据骰子最终停留的区域与朝上的点数计算得分并展示在 UI。
- 保持范围克制，不做进阶数值系统与复杂 UI；打好核心“手感”。

### 技术栈
- 渲染：React + TypeScript + Vite + `@react-three/fiber` + `three`，辅以 `@react-three/drei` 常用辅助。
- 物理：`cannon-es`（刚体、碰撞、约束、亚步进）。
- 状态：`zustand` + `immer`（轻量、直观）。
- 声音：`howler`（滚动、碰撞、拍击反馈）。
- 构建/开发：Vite 及默认脚本。

### 核心系统设计
- 骰子与桌面
  - 桌面：静态刚体（大平面），带摩擦系数与反弹系数；四周可加低矮围栏避免骰子飞出。
  - 骰子：动态刚体立方体（Phase 1 可用直角盒体+简单贴图，后续迭代倒角与法线/光照）。
  - 物理步进：60 FPS 目标，必要时 `fixedStep` + `substeps` 保稳定。

- 拍击交互（随机性与技术性）
  - 输入：鼠标/触控点击桌面；以相机射线检测到的桌面坐标为“落点中心”。
  - 力量：固定基础脉冲 + 小幅随机扰动（±5%），后续可加入长按蓄力/拖拽方向控制。
  - 影响范围：半径 R 内的骰子接收与距离成衰减的向上+法线切向脉冲。
  - 技术性来源：玩家选择拍击位置和时机（靠近骰子侧边 vs 顶部影响滚动姿态）。

- 骰子停止与点数读取
  - 停止条件：线速度与角速度均低于阈值（如 v<0.05, ω<0.05）并持续 t≥0.6s。
  - 朝上面判定：根据骰子四元数取世界坐标系下的六个面法向量，选择与世界 +Y 最接近者映射为点数（1–6）。
  - 稳健性：在临界摇摆时延迟判定，避免抖动误读。

- 区域记分
  - 桌面划分为若干可视区域（Phase 1：同心圆/网格二选一；建议简洁网格）。
  - 得分规则（示例）：`区域基分 × 骰子点数`，例如中心区×3，内圈×2，外圈×1。
  - 结算时机：每次拍击后，当所有骰子进入“停止”状态统一结算并累加到总分。

- UI/UX
  - 右上角：总分显示与最近一次结算浮动提示。
  - 底部：主按钮“拍一下（Slap!）”，Phase 1 固定强度。
  - 左上角：调试开关（显示物理调试、区域边界、FPS）。
  - 视觉：基础环境光与主方向光，简洁桌面材质，骰子基础贴图即可。

- 音效
  - 拍击音（触发时）。
  - 骰子与桌面/边界的碰撞声（基于碰撞强度调整音量/音高）。

### 架构与目录
- `src/game/`：与玩法和物理相关（世界、骰子、桌面、判定、系统）。
- `src/ui/`：React 组件（HUD、按钮、调试面板）。
- `src/assets/`：贴图与音效占位。

建议关键模块（命名示例）：
- `game/physics/physicsWorld.ts`：初始化 `cannon-es` 世界、步进、碰撞参数。
- `game/entities/Dice.tsx`：渲染+物理绑定的骰子组件，含停止检测与点数读取。
- `game/entities/Table.tsx`：桌面与边界。
- `game/systems/slapSystem.ts`：将点击事件转换为对范围内骰子的脉冲。
- `game/systems/scoring.ts`：区域映射与得分计算。
- `game/state/store.ts`：`zustand` 全局状态（分数、骰子列表、调试开关）。

### 里程碑
- M0（已完成）
  - 脚手架：Vite React+TS 项目创建与依赖安装、基础目录搭建。

- M1 核心可玩（本期交付）
  - 骰子物理与渲染：1–3 颗骰子在桌面上稳定滚动与停止。
  - 点击拍击：基于点击落点对附近骰子施加脉冲（含轻微随机扰动）。
  - 停止判定与点数读取：稳健映射 1–6。
  - 区域记分：基础网格区域 × 点数，结算并显示分数。
  - 基础音效：拍击与碰撞。

- M2 可玩性提升（下一期）
  - 蓄力/方向控制；多种桌面区域与奖励；骰子外观倒角与贴图美化；本地存档与基础增量产出（被动收益）。

### 风险与对策
- 物理不稳定/穿透：使用较小时间步+亚步进、合理反弹与摩擦、避免极端初速度。
- 点数误判：引入速度阈值与稳定窗口时间，必要时在静止后再次取样确认。
- 性能：限制骰子数量（Phase 1 ≤3），当系统静止时暂停高频更新。

### 验收标准（Phase 1）
- 在桌面点击后，骰子产生明显、可控的弹跳与滚动。
- 骰子在 2–5 秒内自然停止，UI 显示准确的点数与区域得分，并累加到总分。
- 过程中帧率稳定（目标 60 FPS，低端设备不低于 30 FPS）。

### 开发顺序（建议）
1) 物理世界与桌面搭好 → 2) 单颗骰子稳定滚动与停止判定 → 3) 多骰子 → 4) 点击拍击脉冲 → 5) 区域网格与映射 → 6) 记分与 UI → 7) 音效 → 8) 调试面板与小幅打磨。
